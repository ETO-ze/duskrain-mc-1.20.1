# DuskRain 性能诊断

服务端采用锁定版本的 spark，仅管理员/控制台使用。普通玩家菜单不提供诊断入口。

| 命令 | 用途 |
|---|---|
| `/spark tps` | 查看 TPS 和 tick 耗时 |
| `/spark health show --memory` | 在控制台查看运行与内存状态 |
| `/spark profiler start` | 开始 CPU 采样 |
| `/spark profiler stop --save-to-file` | 保存本地采样，不上传报告 |
| `/spark profiler cancel` | 取消采样，不上传 |
| `/spark tickmonitor --threshold-tick 50` | 记录超过 50 ms 的 tick |
| `/spark gc` | 查看垃圾回收情况 |

默认在隔离存档采样。分析报告中 Server thread 的高占比调用，再区分区块生成、实体 AI、DuskRain 技能与模组逻辑；高占比本身并不证明存在缺陷。内存转储可能包含运行时数据，仅管理员本地保存，不随 Release 公开。

## A/B 方法

同一台电脑、Java 17、相同 JVM 堆上限、分辨率、GUI 缩放、视距、光影、帧率限制和垂直同步。使用同一备份复制出的世界，固定位置、朝向、时间、天气与活动角色数。先预热，再采样；冷启动和热启动分别记录，不将不同缓存状态混为一组。

记录启动及进世界耗时、堆内存、FPS、低帧指标、帧耗时 P95/最大值、服务端 MSPT P50/P95/最大值。客户端 `FrameProbe` 会记录原始帧间隔、菜单帧数和失焦帧数；出现操作干扰或设置不同的样本不能作为受控对照。空服两次重启不是 20 人压测。

当前原始记录在本地 `docs/qa/v22-*.json` 和测试实例中。新结果应明确运行的 JAR 哈希、模组锁文件及真实/模拟参与者。未测出的提升不填写百分比。

命令来源：[spark 官方说明](https://spark.lucko.me/docs/Command-Usage)。
